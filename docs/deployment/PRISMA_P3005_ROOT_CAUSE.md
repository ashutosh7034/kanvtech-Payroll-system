# ROOT CAUSE INVESTIGATION: PRISMA ERROR P3005 ON RENDER & NEON POSTGRESQL

**Document:** `docs/deployment/PRISMA_P3005_ROOT_CAUSE.md`  
**Date:** 26 October 2026  
**Target Environment:** Render Web Service (`payflow-backend`) | Neon Serverless PostgreSQL (`neondb`)  
**ORM:** Prisma 6.16.0 / 6.19.3  

---

## 1. INCIDENT DESCRIPTION & FAILURE LOGS

During the startup phase of the backend Web Service deployment on Render, the build step succeeded, but the service failed immediately upon executing the start command:
```bash
npx prisma migrate deploy && npm start
```

### Log Output Recorded:
```text
Prisma schema loaded from prisma/schema.prisma
Datasource "db": PostgreSQL database "neondb", schema "public" at "ep-cold-water-b5olieo2.c-7.us-east-2.aws.neon.tech"

Error: P3005
The database schema is not empty. Read more about how to baseline an existing production database: https://pris.ly/d/migrate-baseline
```

---

## 2. VERIFIED FACTS

1. **Live Database Status:**
   - Host: `ep-cold-water-b5olieo2.c-7.us-east-2.aws.neon.tech`
   - Database: `neondb`, Schema: `public`
   - Total Tables Existing: **70 tables** (all matching the modern PAYFLOW enterprise domain model: `Company`, `Employee`, `User`, `Role`, `EmployeeLoan`, `SalaryComponent`, `CorporatePayrollRun`, etc.).
   - Initial Seed Data: 1 Company, 3 Employees, 7 Users, 12 Roles, 13 Salary Components, 12 Payroll Periods.
   - Migration Table: Prior to repair, `_prisma_migrations` **did not exist** in `neondb`.

2. **Repository Migration Directory Status:**
   - Folder: `backend/prisma/migrations/20261014055419_init/`
   - File: `migration.sql` (1,258 lines)
   - Git Commit: `c365fe43f5c782bef9f2e955d100bb0ef0ec46e8` (14 October 2026)
   - Defined Entities: Legacy academic prototype models (`Institution`, `OrganizationalUnit`, `CadreType`, `GpfTransactionType`, etc.).
   - Model Match with `schema.prisma`: **0% overlap**. The entities in `20261014055419_init` do not exist in `schema.prisma`.

3. **Prisma Migrate Behavior:**
   - When `prisma migrate deploy` executes against a database that has tables in `public` but no `_prisma_migrations` tracking table, Prisma deliberately halts with `P3005` to prevent overwriting or misidentifying unmanaged production databases.

4. **Git Ignore Masking:**
   - The root `.gitignore` contained `*.sql` without an exception for `backend/prisma/migrations/**/*.sql`. This silently prevented new migration files generated by `prisma migrate` from being tracked by git.

---

## 3. INFERENCES

1. **Provisioning Method:** The 70 tables in Neon were provisioned using `prisma db push` rather than `prisma migrate dev`. `prisma db push` synchronizes schemas without creating or recording migrations in `_prisma_migrations`.
2. **Abandoned Migration Directory:** The original migration `20261014055419_init` was created during early project bootstrapping for a different conceptual model and was left unmaintained as the enterprise HRMS/Payroll domain evolved.

---

## 4. ROOT CAUSE SUMMARY (CLASSIFICATION)

The failure maps directly to **Category A & Category D**:
* **Category A:** The populated Neon database predated Prisma Migrate tracking (`_prisma_migrations` absent).
* **Category D:** The repository’s lone historical migration directory contained obsolete SQL that bore no relation to either the live database or `schema.prisma`.

---

## 5. ACTIONS ACTUALLY EXECUTED

1. Inspected git commit history for `backend/prisma/migrations`.
2. Queried Neon live database schema via read-only introspections (`SELECT current_database(), current_schema()`).
3. Checked for presence of `_prisma_migrations` (returned `false`).
4. Automated schema diff comparison using `npx prisma migrate diff --from-schema-datamodel prisma/schema.prisma --to-url "$DATABASE_URL_UNPOOLED"`. Confirmed `No difference detected`.
5. Created isolated Neon copy-on-write clone branch `test-baseline-repair` (`br-autumn-meadow-b5s0urb3`) and reproduced `P3005`.
6. Updated `.gitignore` to whitelist `!backend/prisma/migrations/**/*.sql`.
7. Created true 70-model baseline migration `20261026000000_init` (1,665 lines).
8. Recorded baseline on Neon production using `npx prisma migrate resolve --applied 20261026000000_init`.
9. Created Point-In-Time recovery snapshot on Neon: `snap-mute-credit-b5cyc9ry` (`pre-release-baseline-snapshot`).
